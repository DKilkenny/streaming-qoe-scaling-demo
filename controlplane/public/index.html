What is this?

This is a small streaming backend with two decoupled paths: a read path that starts playback sessions and serves the catalog, and a write path that ingests QoE beacons (rebuffers, errors, completions) into a queue drained by a pool of workers.

Because the paths are decoupled, playback-start time (VST) stays fast even when the write pipeline is under heavy load — that separation is the point of the architecture, and what this demo is built to show.

The two paths scale independently, each on its own signal: the read/API tier adds or removes API containers behind the load balancer when playback-start latency (VST) climbs — a synchronized play-button rush, like an episode drop; the write/worker tier adds or removes beacon workers based on queue backlog and utilization. They watch different signals and never compete for the same knob. A freshly provisioned instance on either tier takes ~12s to “warm up” before it helps (compressed for this demo — see the honesty note below).

Honesty note: VST, backlog, utilization, worker counts, and API instance counts are measured live from the running stack. The viewer traffic, each worker’s cold-start delay, and each API instance’s saturation point are simulated — they model the shape of a real surge, not literal AWS provisioning times or capacity limits. The cold-start delay itself is compressed to ~12s here so a tour finishes in under a minute; a real Fargate task cold-start is ~60–90s.

VST p95 (SLO <100ms) – Read-path latency, measured live. Decoupled from the write pipeline.
Concurrent streams – Live sessions being tracked right now.
Rebuffer ratio – Share of sessions that stalled. From client beacons.
Playback errors – Share of sessions that errored out. From client beacons.
Beacon backlog – Queued beacons waiting on workers.
Active workers – Processing the queue now. “+N warming” are cold-starting.
Utilization – Incoming beacon rate vs current worker capacity. Can exceed 100% while workers are still warming — that's the gap the scaler races to close.
API instances – Read-tier containers behind the load balancer. Scales on VST.
Playback-start RPS – Play-button rate driving VST on the read path.
